# Milestone 7 — Courses

Create, rename and delete-as-archive courses from the side panel, plus the first-run empty state in the main view.

This plan is self-contained: an agent starting cold should need only this file, `specs/` and `CLAUDE.md`.

## Where this starts from

Milestone 6 landed the shell (commit `01fcb39`): a top bar with the date navigator and the Daily/Weekly control, a
side panel carrying the language switch, and `src/components/app-data.jsx` — the single shared context holding
`selectedDate`, `view`, `courses`, `homework`, `loading`, `error`, `errorCount` and exposing `setView`, `selectDate`,
`goPrevious`, `goNext`, `reload`.

Everything the database side needs already exists and is tested. **Do not write new SQL.** `src/db/courses.js` has
`listCourses`, `createCourse(name, createdAt)`, `renameCourse(id, name)` and `archiveCourse(id, archivedAt)`.
`src/lib/grouping.js` has `sortCourses(courses, locale)` and `compareCourses`. `src/lib/dates.js` has the calendar-date
helpers.

The side panel has a `{/* Milestone 7 puts the course editor here. */}` marker above its `<Separator />`. That is where
the editor goes.

## Decisions taken with Julien on 2026-08-25

These are settled. Do not reopen them.

1. **Deleting a course opens a confirmation dialog** that names the course, says homework already filed under it keeps
   that name muted, and says it cannot be undone. Julien approved the `alert-dialog` shadcn component for this, and
   with it `@radix-ui/react-alert-dialog`.
2. **The editor lists active courses only.** Archived courses survive on their homework entries, muted, exactly as
   the specs require — but they do not appear in the panel. There is no un-archive action anywhere, and this milestone
   does not invent one.
3. **Creating and renaming happen inline in the list.** One text field at the top adds a course; the pencil on a row
   turns that row into a field with confirm and cancel. No dialog for either — the whole editor is one list.
4. **Only the empty state lands now.** When no course exists the main view explains a course is needed first and
   offers a button that opens the panel on the course editor. Disabling "add homework" belongs to milestone 9, where
   that button is born.

## Not in this milestone

- The homework card and its Markdown (milestone 8)
- Creating, editing or deleting homework entries, and the course picker they use (milestone 9)
- Export and import (milestone 10)
- Un-archiving a course, from anywhere, by any route

## Steps

Work test-first throughout: the behaviour below is pinned by `specs/functional-specs.md` and `specs/data-model.md`, so
tests may be written before the code. Where those specs are silent, the decisions above are the contract.

### 1. `nowInstant()` in `src/lib/dates.js`

> **Corrected while executing.** This step was wrong: `nowInstant` already existed in `src/lib/instants.js`,
> committed with milestones 0–4, injectable as `nowInstant(clock = Date.now)`, milliseconds trimmed, with its own
> tests — and `src/lib/dates.js` already points at it. Nothing was written; the editor imports the existing helper.
> The "clock read in exactly two places" comment in `dates.js` is still accurate for that file and was left alone.

`createCourse` and `archiveCourse` both take an instant, and nothing in the codebase produces one yet — milestone 4
passed them in from the caller and no caller existed. `specs/data-model.md` line 24: instants are ISO-8601 UTC strings
such as `2026-08-21T09:14:03Z`.

```js
export function nowInstant(now = new Date()) { … }
```

Injectable `now`, exactly like `todayDate`. `toISOString()` gives `2026-08-21T09:14:03.000Z` — decide whether the
milliseconds stay or are trimmed to match the spec's example, write the test that pins whichever you choose, and say
which in your summary. This is the **third** place in the codebase that reads the local clock; the existing two are
`todayDate` and `toLocalDate`, and `src/lib/dates.js` documents that count. Update that comment.

### 2. Course-name validation in `src/lib/courses.js` (new, pure)

`specs/data-model.md` line 55: the unique index is *"a backstop, not validation: the course form trims before it
saves"*. So the trimming and the duplicate check live here, pure, tested without React.

```js
export function normalizeCourseName(name)          // trims; collapses nothing else
export function validateCourseName(name, courses)  // → null, or a reason string key
```

The reasons this milestone needs: an empty name after trimming, and a name already taken by an **active** course.
Compare case-insensitively and locale-aware — `sortCourses` already establishes that names are compared in
JavaScript, never in SQL. Renaming a course to its own current name is **not** a duplicate.

Return a key (`"empty"`, `"duplicate"`) rather than a translated string: this module must not import i18next.

### 3. `src/components/course-editor.jsx`

The list, inline add, inline rename, and the delete button that opens the dialog. It reads `courses` from
`useAppData()` and calls `reload()` after every successful write, so the whole application sees the change at once —
the main view's empty state included.

- Active courses only, ordered with `sortCourses(courses, i18n.language)` — never `ORDER BY`
- The add field and the rename field both validate through step 2. A rejected name is reported **inline, on the
  field** (`specs/functional-specs.md`: *"A problem the student can fix in place … is reported inline, on the field
  itself"*), never as a toast, and never by silently doing nothing
- A write that fails is a failure the student cannot act on: that one goes to `onError`, the same callback the
  language switch already uses, and the panel's owner turns it into a toast. Do not raise a toast here
- `Enter` confirms and `Escape` cancels a rename. `Escape` must not also close the panel while a field is open —
  check this in the real application, not only in jsdom
- Every button carries an accessible name from the catalogs, including the icon-only pencil and bin

### 4. The delete confirmation

An `alert-dialog` naming the course, per decision 1. Wire the confirm to `archiveCourse(id, nowInstant())` followed by
`reload()`. `archived_at` is the only write — there is no `DELETE FROM courses` anywhere in this milestone, and
`specs/functional-specs.md` is explicit that there is deliberately no second code path for a course no homework has
ever used.

### 5. Mount the editor in the side panel

Replace the `{/* Milestone 7 puts the course editor here. */}` marker. Keep the existing `<Separator />` between the
language section and the editor.

The panel currently manages its own open state through `<Sheet>`'s uncontrolled default. Step 6 needs to open it from
outside, so lift that to a controlled `open`/`onOpenChange` pair owned by whoever renders `SidePanel` — probably
`TopBar`, threaded from `App`. Keep `SidePanel` free of any decision about *why* it opened.

### 6. The first-run empty state

When `courses` is empty and the read is not in flight, the main view shows the empty state instead of the day or week:
a heading, one line explaining homework needs a course to file it under, and a button that opens the side panel.

Both views are affected. Put it in `App.jsx`'s `MainView`, above the daily/weekly branch, so neither view has to know
about it.

Do not show it while `loading` is true and do not show it after a failed read — a database that could not be read is
not the same thing as a student with no courses, and telling them to create one would be a lie. `error` and
`errorCount` are already in the context for exactly this kind of question.

### 7. Catalogs

New keys under a `courses.*` section in both `src/i18n/en.json` and `src/i18n/fr.json`: the section heading, the add
field's placeholder and button, the rename and delete accessible names, confirm and cancel, the two validation
reasons, the dialog's title, body and buttons, and the empty state's heading, body and button.

`catalogs.test.js` enforces key parity but cannot see a key nothing renders. **Only add keys that are actually
rendered** — an unused `sidePanel.close` slipped through in milestone 6 and the architecture review caught it.

French is not a translation of English word-for-word: write what a French-speaking child would read.

## Known traps

- **`sortCourses`, never `ORDER BY`.** `Éducation physique` after `Zoologie` is the exact bug the specs call out
- **The instant, not the calendar date.** `archived_at` and `created_at` are `2026-08-21T09:14:03Z`, not `2026-08-21`.
  `todayDate()` is the wrong helper here
- **Trim before you validate and before you save.** `"  Maths  "` and `"Maths"` are the same course
- **The unique index will throw** if the duplicate check is ever bypassed — `(code: 2067) UNIQUE constraint failed`.
  That is the backstop doing its job, and it still has to reach the student as a failure rather than as a blank screen
- **`reload()` after every write.** The context does not observe the database; nothing refreshes on its own
- **A dialog inside a drawer is two focus traps.** Verify `Escape` in the real window: the expectation is that it
  dismisses the dialog and leaves the panel open
- **jsdom cannot see colour**, so "muted" is not assertable there. Assert the class or the structure, and confirm the
  appearance on screen
- **Radix defers a left-button outside-click dismissal to the `click` after `pointerdown`**, so a test that fires only
  `pointerDown` cannot fail. `shell.test.jsx`'s outside-click test fires the whole sequence — copy it
